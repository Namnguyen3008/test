# Deployment guide

Local Compose is the supported integration environment. It applies Alembic through a one-shot migration service before API/worker/scheduler startup and publishes PostgreSQL/Redis on loopback only. Production deployments use `infra/helm/vmec`, external managed PostgreSQL/pgvector and Redis, pre-created Kubernetes Secrets, TLS ingress, encrypted backups and approved runtime data.

Before rollout, render the chart, run the migration hook against an isolated target, import the approved release, build both embedding indexes, validate model capabilities and run smoke/E2E/security gates. Pre-provision the read-only `runtimeData.existingClaim` with exactly `APPROVED_CORPUS_MANIFEST.json` and the compiled `vmec_catalog.sqlite3`; do not bake source data into the image. Build the web image with `NEXT_PUBLIC_API_URL` matching the API TLS host. Use immutable image digests in production values. Never put source artifacts or runtime secrets in an image or ConfigMap.

Roll out API, worker and the singleton scheduler before web; verify readiness and aggregate PHI-safe metrics, then gradually increase traffic. A failed migration, missing approved corpus, forbidden model configuration, missing index or authorization regression is a release stop. Rollback uses the previous images and embedding index metadata; database rollback requires an explicitly tested migration/restore plan.
